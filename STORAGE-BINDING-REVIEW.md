# Storage binding review (C#) — Stage 0

**Status:** investigation of C# package/binding and deployment viability for the broad storage candidate set. This is not a storage selection; [ARCHITECTURE.md](ARCHITECTURE.md) still owns the requirements, and [STORAGE-RESEARCH.md](STORAGE-RESEARCH.md) owns the harness-level comparison. No schema, layout or engine is chosen here.

Inspected 2026-11-04 on Windows 11 x64, .NET SDK 10.0.403. Package metadata from nuget.org flat-container APIs and package nuspecs; documented behaviour from official engine/library docs; probes as listed below with an explicit tested-vs-documented split per engine. All probe artifacts live in `%TEMP%\urd-binding-review-hx7\` (restore from official nuget.org only; no global installs, no toolchain changes, no repository file changes outside this report).

## Probes — tested vs documented

One small console app per native engine, OS-temp isolated, net10.0, official feeds:

| Probe | Exact result | What that actually proves | What remains documented-only |
| --- | --- | --- | --- |
| `Microsoft.Data.Sqlite` 10.0.14 | PASS ×5: WAL/synchronous PRAGMAs; 100-record insert transaction; `ORDER BY ord DESC` range (50 recs); `DELETE >= ord` suffix; close/reopen with count preserved | Native `e_sqlite3` resolves and loads automatically via the bundle on net10.0; ADO.NET surface covers all needed operations on .NET 10 | Power-loss flag combinations; concurrent multi-writer behaviour; `SqliteCommand.Cancel` effectiveness under load |
| `RocksDB` 11.12.0.7641 (curiosity-ai) | PASS ×5: 100-put `WriteBatch`; iterator `Seek` ordered range (50 recs); `DeleteRange` suffix edit with sentinel end key; reopen persistence; native auto-load | Single-package restore works on net10.0; `DeleteRange` exists but only with explicit key-length overloads (null/unbounded end rejected by the engine as "end key comes before start key") | WAL/flush durability combinations under crash; compaction behaviour; `FlushWAL` absence verified by reflection only, not runtime impact |
| `LightningDB` 0.23.1 | PASS ×4: 100-put write txn; `SetRange`+`Next` ordered read (50 recs); cursor-delete suffix (50); reopen via env re-open, `DatabaseStats.EntryCount` verified | Bundled LMDB 1.0.1 native loads on win-x64 net10.0; sorted-key cursor model fully covers range reads and suffix edits; 64 MB `MapSize` reservation worked as address-space only | Windows map-resize behaviour beyond the documented fixed-map limitation; NOSYNC/NOMETASYNC trade-offs; cancellation mid-transaction |

Not probed (no native-binding risk or no viable package): LiteDB (managed), encodings (managed), Tsavorite (no official package — that absence is itself the finding). Reflection probes against the installed assemblies were used sparingly to confirm binding API existence (`DeleteRange` overloads, `FlushWAL` absence, LightningDB cursor API), not runtime behaviour.

## Encoding candidates (record payloads)

All are managed assemblies; none carries native-binding risk, so Stage 0 metadata is adequate. Version anchors from nuget.org (2026-11-04):

| Encoding | Package | Current | License | Notes |
| --- | --- | --- | --- | --- |
| MessagePack-CSharp | `MessagePack` | 3.1.12 stable (4.0.0-preview.2 in flight) | MIT | Source-generated formatters (AOT-safe), wide adoption, .NETStd2.0/net8+ |
| Protobuf (official) | `Google.Protobuf` | 3.36.2 stable (3.37.0-rc1, 4.0.0-rc2 exist) | BSD-3-Clause | Steady ~3-week release cadence; requires .proto codegen toolchain |
| protobuf-net | `protobuf-net` | 3.4.40 | Apache-2.0 | Attribute-based, no codegen; 2.x line critical-fixes only |
| MemoryPack | `MemoryPack` | 1.21.4 | MIT | Zero-encoding, source-generated, .NET 8+ focused; newest/smallest community |

Recommendation for the harness: any of these is deployable; MessagePack 3.1.12 is the most conservative pin (mature, MIT, source-gen, no proto pipeline). **Compression:** Brotli is built into the BCL (`System.IO.Compression`); adding zstd/deflate-variant packages is unwarranted unless a proven need appears (one is already dragged in transitively by RocksDB via `ZstdSharp.Port`).

## Suggested harness-only version pins (not a selection)

- `Microsoft.Data.Sqlite` **10.0.14** (with transitive `SQLitePCLRaw.bundle_e_sqlite3` 3.0.5 / `SourceGear.sqlite3` 3.53.4)
- If KV engines are ever revisited: `RocksDB` **11.12.0.7641** (single-package) — never the stale `RocksDbSharp` 6.2.2 path; `LightningDB` **≥ 0.23.1** (LMDB 1.0 format)
- Encoding fallback set: `MessagePack` **3.1.12**, `Google.Protobuf` **3.36.2**, `protobuf-net` **3.4.40**, `MemoryPack` **1.21.4**

## Not established by this review

- Which layout variant Urd should use; the owner has not selected storage or a layout.
- Probe findings transfer exactly to other RIDs (macOS/Linux natives restored but not exercised).
