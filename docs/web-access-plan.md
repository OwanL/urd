# Web search and reading

Status: implementation plan, not shipped behavior. Scope: public, read-only web access for any tool-capable model. Urd owns both tools. No provider-native answers, search-provider picker, personal browser profile or general-purpose browser control.

## Tool contract

- `web_search(query)` sends the same nonempty query to You.com free MCP and public Bing via full headless Chromium, concurrently, on every call. Neither is a fallback. Request up to five organic hits from each; never open a hit merely to list it. The model sees title, destination URL, bounded snippet, optional publication date and source(s). Snippets are leads, not citations verified by Urd. Do not substitute answer boxes, ads or generated summaries.
- Merge deterministically: alternate ranks, You.com first, keeping the first appearance and recording both sources and original ranks for duplicates. Decode known Bing redirect URLs; compare normalized scheme/host/default port and remove known tracking parameters. Preserve meaningful query parameters, paths and fragment targets; prefer an occasional duplicate over merging distinct documents. Return all remaining hits (at most ten). No LLM reranker.
- Give each source an independent deadline. Report each as completed (including zero hits), blocked, rate-limited, timed out or failed. A usable response plus a failed source is partial; two failures are not “no results.” Distinguish a confirmed Bing empty state from an unrecognized page layout. Do not retry challenges. On cancellation stop both operations locally.
- `web_read(url)` accepts a public HTTP(S) URL, including URLs not returned by search. For HTML, navigate in Chromium with JS enabled on the first read. Use the navigation response's content type or intercepted download to route PDF/plain text/JSON to bounded extraction instead of scraping a viewer; avoid fetching a document twice where feasible. Strip navigation/boilerplate where possible, retain headings, paragraphs and meaningful links. Return final URL, title, readable text, extraction status and explicit truncation. A scanned PDF without a text layer is unsupported in v1; no OCR. No automatic recursive reading.
- Completion means useful rendered content within a deadline, not global network idle. Wait for the document and a short bounded text-settling interval; test delayed JS and pages that never stop polling. Don't click, sign in, solve challenges or invent selections for product variants. Report blocked, timed out, unsupported and empty distinctly. Treat retrieved text as untrusted source material, not instructions.

## Runtime and integration

- Use ordinary `AgentTool`s, composed in `SessionManager.CreateToolCatalog`. Keep network tools independent of shell/Git Bash availability; qualify the invoker's working-directory assumption. Put URLs, status and text in `ToolOutput.Text`, not just `Details`. Use the existing transcript and cancellation paths. No custom UI, database schema or general MCP server registry required.
- Use a fixed You.com free MCP client (`you-search`, count five, no page extraction), via the selected .NET MCP SDK. Bing adapter owns organic-card parsing; search merging owns neither transport. Use a pinned full Chromium build with a compatible automation library, not a user's Edge profile. Qualify the .NET browser driver and unattended provisioning before embedding either.
- Provision the platform-specific browser atomically on first use, outside the repository, in the app's managed cache. Coalesce concurrent installs and launches; show first-use download/progress in the existing tool status if supported. No browser at Urd startup. Browser setup failure must not discard You.com results. Document that every search sends the query to both services. Public endpoint capacity and permission to distribute automated Bing search remain separate from technical qualification.
- One browser process per backend host; isolated temporary contexts per operation, a bounded work queue and no persistent cookies. Proposed starting limits: two active contexts, 60 s idle teardown, 15 s per search source after provisioning, 20 s per read, 32 KiB returned text and 10 MiB document input. These are tuning targets, not measured guarantees. Bound provisioning and queue waits separately. Cap subresource traffic and redirects; on cancellation, crash or shutdown release owned pages/processes without closing another session's work. Expose no browser control endpoint to web pages.
- Public-web only: enforce destination restrictions for navigation, redirects and browser subrequests, including resolved addresses; block loopback/private networks and local files, including Urd's local server. Use an enforceable egress boundary, not just an initial URL string check. Preserve browser sandboxing. No credentials or session data passed to sources.

## Delivery and acceptance

1. **Qualify dependencies and lifecycle.** On Windows first, prove clean-cache automatic install, warm reuse, concurrent first calls, SDK negotiation, cancellation and idle/shutdown cleanup. Record download, warm and cold latency, peak process-tree memory and surviving processes. Don't claim support on other platforms until repeated there.
2. **Deliver merged search.** Use recorded organic pages and controlled MCP responses to verify rank order, duplicate provenance, disjoint hits, empty pages, markup drift, one-source failure, both-source failure and cancellation. No mandatory outbound network in the local test suite.
3. **Deliver reading.** Controlled fixtures: static article, delayed JS-only content, perpetual polling, redirects, challenge, large body, PDF with/without text, JSON/text, private destination and subresource. Verify model-visible URLs/status, bounded text, useful partial output vs failure, and isolation under concurrent sessions.
4. **Qualify the actual tools end to end.** Replay the five real tasks from discovery (NZ Hirsch strap, pnpm deploy, CLI comparison, Albion market, Bowles/Choi paper) plus the invented identifier. Give the model the merged list and the same read budget per task; verify each cited page against the original criteria. Record answerable tasks, unsupported claims, first useful rank, source contributions, p50 latency and cleanup. The earlier 5/5 union was measured across independent result sets, not an end-to-end score. Keep live runs local and separate from deterministic tests. Stop on access gates; no challenge bypass.

Out of scope: authenticated pages, arbitrary interactions, automatic consent clicks, OCR, a provider framework, paid fallbacks, proactive crawling, and multimodal screenshots as model output.
