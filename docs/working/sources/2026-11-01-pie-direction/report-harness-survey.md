# Coding-agent customization and distribution: implications for Pie

**Research snapshot: 2 November 2026.** This surveys current upstreams, not Pie’s pinned Pi version. “UI” distinguishes supported extension surfaces from changing source. MCP extends tools/context; it is not a general GUI-plugin protocol. Most products own their agent loop, even when using shared model libraries. Availability of features is not evidence of their retention or maintenance economics.

## Comparative survey

CLI updates and separately versioned marketplace/local plugins. | **Cursor / Windsurf** | Closed products forked from VS Code; rules/skills/MCP/hooks plus inherited editor extensions. Editor webviews are not unrestricted access to native agent panels. Windsurf became **Devin Desktop** June 2, 2026; [FAQ](https://docs.devin.ai/desktop/devin-desktop-faq) confirms OTA updates and preserved editor features. Cursor now packages [agent plugins](https://cursor.com/docs/reference/plugins). These are funded product forks, not evidence that personal forks stay cheap. |
| **Amp** | Instructions, skills, MCP and executable TS/JS plugins. **Bounded UI hooks**: dialogs, commands, quick actions, portal/pane actions; capabilities differ by client. | Own orchestration; CLI background/manual updates. Plugins load from scoped files or shared repositories/URLs. [Plugin contract](https://ampcode.com/docs/customize/plugins), [CLI](https://ampcode.com/docs/cli). Explicit limits and client-specific behavior show the ongoing contract burden behind “UI plugins.” |
| **Crush / Charm** | JSON settings, providers, MCP, hooks, skills and themes. No arbitrary GUI-plugin surface established; terminal TUI. | Own agent built on Charm’s Fantasy framework, not another installed coding agent. Package-manager/releases deliver updates. Current FSL-1.1-MIT is source-available, converting after two years—not equivalent to Pie’s present open-source licensing. |

## Protocols: useful boundary, not universal compatibility

[ACP](https://agentclientprotocol.com/) separates agent execution from editor presentation; [custom methods/metadata](https://agentclientprotocol.com/protocol/v2/extensibility) permit extensions. Codex app-server, Pi RPC/SDK and OpenCode server offer similar host boundaries with different contracts. None automatically transports arbitrary agent-specific GUI widgets. MCP addresses a different boundary. Supporting every protocol immediately would multiply maintenance, not simplify it.

## Recommendations for Pie

1. **Choose a bounded hybrid (D).** Keep instructions, skills, named agents, providers and MCP as supported configuration. These are portable workflow assets, not needless plugin machinery. Retain a small executable-tool boundary where it removes repeated integration work.
2. **Ship matching source; do not make personal forks the default customization mechanism.** An agent can write a patch; it cannot erase reconciliation, testing, build-toolchain or distribution costs. “Users already have an agent” does not make them willing application maintainers. Pi itself contradicts that framing: self-modification coexists with packages and hooks.
3. **Do not build a general GUI extension platform now.** Start with structured tool results and a few built-in renderers; add a narrowly versioned renderer contract only after repeated real demand. OpenCode’s migration/experimental surfaces and Amp’s client differences illustrate the obligation incurred.
4. **Do not justify a fresh repository by this survey.** Codex rewrote against concrete installation/security constraints; that is not evidence for rewriting Pie. Isolate its engine boundary, measure fork maintenance, then remove specific unused dependencies. Replacing Pi means inheriting its loop/provider/session work, not merely deleting lines.
5. **Prioritize boring delivery.** Fresh-machine onboarding, small reliable updates, rollback, separately pinned executable packages, and reproducible source builds beat customization maximalism. Pilot one external-agent adapter if it serves real users; preserve Pie’s valuable orchestration rather than forcing it through the lowest common protocol denominator.
