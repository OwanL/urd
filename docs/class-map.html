01Hosting and HTTP

Four classes compose and expose the backend. ServerOptions and the nested content-query record support them.

Host composition

Program.RunServerAsync owns the app, directory lease, store and created client. Its composition arrows represent a server-run lifetime, not instance fields on the static class. Core borrows the store/client. The normal server uses FakeChatClient; its client-factory overload is a composition seam for tests. Disposal follows successful HTTP and Core draining, not client disconnection.

HTTP boundary

Details, constraints & source references

LocalBrowserGate admits requests by readiness, loopback, Host, Origin and the API marker; its edge is pipeline order, not a direct reference to SessionRoutes. SessionRoutes.ContentQuery is private and nested. Routes translate HTTP without owning execution policy. Reads accept request cancellation; admitted input and Stop intent do not belong to the HTTP connection's lifetime.

Source: Program, ServerOptions, FakeChatClient, LocalBrowserGate, SessionRoutes.

02Sessions, input and Stop

The manager owns canonical handles; each session coordinates its own state and run. Shared dependencies and data contracts are shown separately so they do not obscure this ownership structure.

Session lifetime and locks

The two lock edges name the same type but separate instances. AsyncLock.Handle releases its acquired semaphore on disposal. SessionManager and sessions borrow SessionStore and IChatClient; the manager snapshots configured tool references and passes them along, without taking ownership of tool disposal. Model/tool work and cancellation callbacks run outside the session lock; guarded storage calls enter it.

Identity and input contracts

SessionRecord is the store-to-manager identity value used to construct a handle. An InputReceipt retains the exact command and its original decision. Acceptance links it to a run; it is not a model answer.

Stop acknowledgement versus run settlement

Details, constraints & source references

In this newer snapshot SessionBase.RequestStopAsync is public and returns StopReceipt. For an owned run, it signals cancellation and attempts to save Stop intent; it does not wait for cleanup. ExecutionResult is published after owned work, cleanup and saved settlement. Do not read Requested as Settled. No subagent/descendant runtime is implemented here; this map does not qualify descendant Stop behavior or imply that stopping one run stops separate independent worker chats.

Source: SessionManager, SessionBase, PrimarySession, AsyncLock and Handle, SessionRecord, Input contracts, Stop contracts, ExecutionResult and outcome.

03Execution and model data

Execution owns the model/tool work lifetime, accumulation interprets updates, and the writer batches text. Private error classes are included in section 6, rather than omitted from the atlas.

Execution collaborators

LlmResponseAccumulator.BoundedJsonStream enforces the tool-JSON size limit while freezing borrowed values. SessionExecution borrows IChatClient, AIFunction objects and its SessionBase; persistence callbacks return through that session's guard. The writer's save callback returns through execution to the session. These shared boundary edges are described here, not misrepresented as owned dependencies in the diagram.

Model requests, chunks and tools

Details, constraints & source references

The dotted ID links are value correlations, not object references. ChatMessage and JsonElement are external types. The request data is prepared by storage before the model call; output chunks and request outcomes travel back through the session. A final text chunk is not whole-run settlement. The accumulator supports complete fake-model calls, not qualified provider-native deltas.

Source: SessionExecution, LlmResponseAccumulator, LlmResponseWriter, Request/chunk/outcome records, Tool records.

04Storage classes

All twelve storage classes appear here. They share a single Database; the helpers do not each open their own connection. The private settlement and message-metadata records are included too.

Store, database and identity

SessionStore also owns the write/read helpers in the next two views; its property list makes those connections explicit without repeating every line. Database serializes all access to its connection and owns transaction lifetimes. DatabaseSchema initializes/migrates schema v4 and connection pragmas.

Durable writes

InputStorage keeps exact admission decisions and delivery membership. RunStorage claims requests, records Stop status and settles runs; RunStorage.Settlement is its private decision value. OutputStorage saves immutable chunks and completed request/tool-call facts. ToolStorage saves start markers and results around external invocation; a database transaction does not roll back tool effects. RunStorage creates RequestContextReader during a claim, inside that same write transaction.

Readers, context and text

Details, constraints & source references

SnapshotReader reuses MessageContentReader in one snapshot read transaction. The private MessageContentReader.MessageMetadata describes committed segments, not a second message store. RequestContextReader assembles model context within the claim transaction. Read pages are bounded; context assembly is not similarly bounded, and holds the shared connection lock.

Source: SessionStore, Database, DatabaseSchema, SessionStorage, InputStorage, RunStorage, OutputStorage, ToolStorage, RequestContextReader, SnapshotReader, MessageContentReader, StorageText.

05Snapshot and content records

These are detached read values, not live sessions. Listing them separately keeps the runtime diagrams readable without pretending the data model does not exist.

Snapshot views

SessionBase merges the stored snapshot with its live admission fence and local stopping state. The public snapshot is therefore not just a renamed storage record. Both carry bounded message previews and independently selected run/settlement facts.

Message identity and paging

Details, constraints & source references

The page's three cursor fields are From, Next and AvailableThrough. Offsets are UTF-8 bytes inside a segment. HasMore describes the current committed tail; IsClosed describes whether more message bytes can arrive. Neither substitutes for saved run settlement.

Source: SessionSnapshot, StoredSessionSnapshot, Message records and role.

06Error classes and private execution signals

These four classes are easy to miss in an overview. Two are public Core exceptions; two are private nested execution signals. Their different roles are preserved rather than folded into a generic error box.

Details, constraints & source references
  • InputConflictException: an input ID was reused with a different original command.
  • HistoryRevisionConflictException: a content read targets a revision that is no longer current.
  • SessionExecution.OutputRejectedException: the current run no longer accepts that output.
  • SessionExecution.OutputSaveException: saving output failed; this is not an ordinary model failure.

The other nested helpers are explicitly drawn with their users: AsyncLock.Handle in section 2, LlmResponseAccumulator.BoundedJsonStream in section 3, RunStorage.Settlement and MessageContentReader.MessageMetadata in section 4, and SessionRoutes.ContentQuery in section 1.

Source: InputConflictException, HistoryRevisionConflictException, Execution signals.
